# 制作与验收细则

## 每集输入与工作记录

收集原视频、用户明确指定的集数、用户指定的风格变化，以及封面参考或配音文件。未给集数先询问，不能继承上一集。记录选段在原片的起止时间，逐句转录与翻译、知识点原句、回听起止时间、`怎么用` 文稿、新例句及其中文、对应配音文件。每个学习点还记录选入理由与主讲/顺带积累层次；这个层次只服务策划，不改变字幕高亮颜色。原片和用户给的音频只作输入，生成中间文件与成片保存在本集工作目录。

建立一份本集 manifest（Markdown、CSV 或 JSON 均可）记录：期数、输入文件及来源、源视频版本、选段时间码、知识点与确认状态、字幕/讲解文稿版本、各知识点对应的 Fish Audio 文件、兔子动画/升级音效来源、输出文件名与版本、质检结果、用户成片确认状态、总卡版本。每次替换素材或修改文稿，更新对应记录，避免混用旧音频和旧视频。只记录文件路径/文件名与版本，不复制不必要的个人信息或密钥。

本公开版只提供可复用的制作规范，不包含任何单集脚本、原片、配音或时间码。按本集素材建立视频、句界、配音、期数和输出文件的映射。

## 制作节奏与交付顺序

1. **输入门**：确认原片可读、期数明确、本集目标清楚。缺期数先问期数；缺原片或关键参考素材，请用户上传。素材不完整时可先做不依赖该素材的工作，并列明阻塞项。
2. **选材确认门**：先给候选片段、原片时间码、准确英文、自然中文、学习价值及主讲/顺带层级。请用户确认片段和知识点；若用户要求讨论，继续讨论并更新方案，确认前不做最终剪辑。
3. **文稿与配音交接门**：逐点展示 `怎么用` 全文、新英文例句及自然中文，请用户确认表达和例句。锁定文稿版本后，提供逐点 Fish Audio 配音稿，并请用户在 Fish Audio 网页端手动生成、上传音频。当前使用免费版流程，不能假设可由 API 自动生成或克隆。每个音频单独标明对应知识点；可按“一点一个音频”交付，也可让用户给出合并音频及准确分段对应关系。仅当听感或内容有歧义时询问是否重录；不得凭文件名猜台词、顺序或对应点。稿件更改后必须重新取得与新稿匹配的音频。尚缺音频时继续字幕、原片剪辑、知识卡版式等独立工作，但不得把不完整音轨交付为完整成片；向用户明确列出待提供的音频。
4. **合成与验收门**：音频和映射齐全后合成，按下文逐项验收并整理预览/截图、时间轴和素材版本清单。发现硬伤先修复并复查受影响项目。手机播放安全区如无法凭现有截图确定，询问目标平台或手机预览素材；不把安全区数值当通用平台规范。
5. **成片确认门**：交付最终候选视频及时间轴，明确请用户确认成片。记录确认的具体文件名/版本。没有确认前，总卡只能按用户要求提供并标记为预览。
6. **总卡与归档门**：确认后制作单张竖向 9:16 总卡；成片任何改动若影响内容、帧图或期数，则同步更新总卡和时间轴。归档最终 MP4、抖音时间轴、确认版总卡、字幕文件、逐点文稿/配音、素材来源与版本 manifest。核对文件存在、名称含正确期数、时间轴对应最终 MP4，且没有把旧版标为最终。

只在缺少必要决策或素材时提问，问题应具体并附上已知选项。例如：期数未给就问“这集是第几期？”；选段/知识点有多种合理方案时给候选供选择；例句语气或中文含义无法从上下文判断时标出歧义；Fish Audio 音频未提供时，发送定稿逐点文稿并请用户按文稿生成后上传；某条录音与卡片无法匹配时请用户指出对应点或重传并命名。不要重复询问已明确的信息，不把可由原片验证的内容转嫁给用户。

## 选段和音频边界

1. 听完整上下文，再选可独立观看的 20–30 秒连续片段。必要时宁可略长，也要让开头与最后一句说完。
2. 为每个讲解点单独定位“含知识点的那一句”，不是整段原视频，也不是只截知识短语。
3. 用转录时间戳找近似位置，再听完整句、检查波形或频谱；句尾在最后可听音素消失后的安静区结束。留出很短的自然余量，不剪进明显杂音。
4. 抽听每个原速与 0.7× 片段的最后一秒，重点听词尾是否被截断。重新裁切后，字幕也要与最新音频匹配。原素材里 `dramatic` 的 /k/、`priorities` 的末尾音节曾被误截，这类词尾必须专项检查。

## 字幕与卡片检查

- 先从目标发布页截图标出顶部搜索栏、右侧按钮和底部标题/评论/进度条的遮挡，再检查最终视频。对更窄、更高的手机做居中裁切预览；不只检查 1080×1920 原图。当前第 58 期版式：卡片约 x=85–995，文字从 x=115 起；顶部人物画面约 x=60–1020、y=230–770；分割线到“怎么用”和“怎么用”到“例句”均留约 45 px。用户指定这些边界后仍要逐卡检查长句与右侧按钮是否冲突；实际 UI 改版或手机裁切不同就重新测量。
- 中英文逐句同轴，翻译自然。字幕句末一般无标点；讲解卡上的完整例句正常使用标点。
- 双语框分别依实际文字宽高绘制，文字和框共用同一中心线；测量最终渲染出的字形范围，不能只按估算字符数画框。当前主画面顶边约 y=520、底边约 y=1128；中文框紧靠上方，英文框位于画面底部内侧，二者无交叠。水印统一用相同的白字与半透明深底圆角样式，分别定位在原片/盲听视频及讲解顶部视频**自身的左上角**，核对其相对内边距而非强行统一画布坐标。
- 检查知识点着色范围是否准确，所有入选表达统一暖黄色。没有把非知识词误染色。
- 卡片照片来自当前讲解句附近，脸完整清楚，字幕可见，水印在该照片左上角；集数写 `第XX期`，不得残留旧期数。卡上仅有“怎么用”“例句”两个内容区；两区保留舒适的内部留白，并让分割线到首卡、两卡之间的距离相等。对较长正文按语义断行，不能拆开词语或将标点挤到行首；左右避开互动按钮。新例句确实不同于原句，且用法地道。
- 配音文稿与卡片“怎么用”的全部文字及新例句逐字对应。录音尾字读完；不要以文件名截断文字推断真实音频内容。
- Fish Audio 音频逐条听检：核对说话内容与定稿文稿、知识点映射、开头/结尾完整、音量和杂音。用户手动生成的素材缺失、无法解码或内容不匹配时，列出具体知识点和文件并请用户补交；不要静默跳过该卡或输出缺音的完整版。
- 用户确认成片后制作独立竖向 9:16 知识点总卡；从原片取 2–3 帧拼背景，逐条核对全部知识点的英文、中文和浓缩用法。检查人物面部没有被标题压住，背景仍看得出源画面，且所有文字在缩略预览下可读。

## 转场和合成

- 两处系列转场各约 2 秒，采用 C 款“画面延续”：把前段实际末帧模糊、压暗为转场背景；兔子约占画面宽度 32%，标题、短横线和小字分层淡入、轻微上移，清晰停留约 0.9 秒；元素先淡出，背景再转为下一段实际首帧。片头用做笔记兔 GIF（`assets/兔莫_做笔记动画.gif`），盲听前用听力兔 GIF（`assets/兔莫_认真听听力动画.gif`）。动画必须使用确实不同的写字或点头姿势帧，不能只平移、旋转静态贴图；两帧之间避免眼睛、笔尖重影。各在进入时播放一次《我的世界》升级音效（素材见 `assets/minecraft-levelup.ogg`），及时开始并保留原音完整尾音，不播放旁白或原片音频。第一个转场结束立即进入第一个知识点回听，不加等待卡；其余回听按既有节奏。转场视频播放完整才切换；以本版前后成片的实际端帧生成转场，不要带入旧版底部水印或旧卡片。回听片段之间仅保留约 0.2 秒自然间隔；这不是转场卡。
- 转场 MP4 导出时按整段时长限制输出，不只用视频帧数限制；历史故障是 `-frames:v` 让音轨在约 1.1 秒处提前结束，尽管原音效和中间 WAV 都完整。分别解码两处**最终成片**的转场音频，确认音效原有的渐弱尾音仍存在，不添加人为回声代替原音。
- 生成透明叠合转场时，用**前段视频实际最后解码帧**作首帧、后段视频实际第一解码帧作末帧，不用近似时间截图。叠合提前数帧到位并保持目标画面，抵消拼接时容器时长取整造成的边界帧丢失。检查的是**最终合成视频**的接缝两帧，而不只是转场素材；两帧不应出现位置跳跃或旧片头闪现。
- 合成前将所有视频片段统一为 1080×1920、30 fps、方形像素、H.264；音频统一为 44.1 kHz、**双声道** AAC。历史故障：单声道知识卡配音与双声道视频直接用 concat 拼接，造成第二个知识点以后丢音。单声道录音应先转为双声道，再合成。
- 静态卡开头给画面约 0.35 秒安定时间，配音全长结束后再留约 0.5 秒。不要按估算字数截断音频。转场和静音段也生成同规格双声道音轨，避免时间戳或布局突变。
- 不直接信任“导出成功”。用媒体信息读取成片时长、画幅、帧率、声道；在字幕段、每个回听、每段讲解配音及无字幕段抽取音频窗口，确认该有声音的地方有非零有效音量。转场仅保留升级音效，其余时段安静。
- 抽帧检查开头、各段交界、至少一张知识卡与无字幕段。确认无黑帧、无旧版本例句、无字幕残留、无遮挡人脸或水印。核对时间轴是根据最终成片时长写的。

## 交付前闭环清单

- [ ] 期数由用户明确提供，素材与版本 manifest 已更新。
- [ ] 选段、逐句字幕及主讲/顺带知识点已给用户确认；变更已经同步到文稿。
- [ ] `怎么用`、新例句及中文已定稿；需要的 Fish Audio 录音齐全，且逐点核对无误。
- [ ] 成片画面、声音、尾音、转场、字幕、手机安全区、知识卡布局均已复查；返工后重新检查受影响部分。
- [ ] 最终 MP4 播放正常；时间轴依据这个最终 MP4 生成；三者（视频、时间轴、manifest）期数与版本一致。
- [ ] 用户确认的成片版本有记录；竖向总卡对应该版本和期数。
- [ ] 归档文件存在且文件名清楚：最终视频、时间轴、确认版总卡、字幕/文稿、配音及素材来源/版本记录。

清单中任何必需项未完成，都要说明具体缺项。若缺用户决定或必须由用户生成的 Fish Audio 音频，提出最小且明确的问题/素材请求，并继续完成不依赖它的部分。
