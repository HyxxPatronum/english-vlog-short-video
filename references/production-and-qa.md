# 制作与验收细则

数值、颜色与时间参数以 [`../config/series-params.json`](../config/series-params.json) 为唯一来源；本文件说明如何核查。修改参数先改 JSON 并运行 `../scripts/qa_series_assets.py`。

## 自动参数验收

- 每集建立结构化 manifest，记录源片起止秒数、字幕样本秒数、最后可听音素的复听时间点与复听状态。通用模板见 `../config/episode-manifest.example.json`。
- 校验程序读取配置、ASS、成片、同画面无字幕基线和逐集 manifest，直接检查画幅、帧率、像素比例、编解码器、采样率、声道、ASS 颜色/透明度/字体/位置/中英同轴、固定水印文件哈希与最终成片像素，以及最终画面的字幕框不透明度。程序生成 JSON 报告，不依赖 LLM 看图。使用 `--strict` 作为交付门；`FAIL`、`WARN`、`REVIEW_REQUIRED`、`SKIP` 均需处理或记录例外，不能把缺素材当通过。
- 原声尾音是否真正结束、人物首尾帧、翻译自然度、手机发布页遮挡和音效听感不能仅凭数值判定。尾音由人听完后把时间点写入 manifest，程序再检查裁切余量；ASR 估计不能代替复听。无字幕基线须与最终视频使用相同画面和时间轴，供像素比较。


## 每集输入与工作记录

收集原视频、用户明确指定的集数、用户指定的风格变化，以及封面参考或配音文件。未给集数先询问，不能继承上一集。记录选段在原片的起止时间，逐句转录与翻译、知识点原句、回听起止时间、`怎么用` 文稿、新例句及其中文、对应配音文件。每个入选表达都记录选入理由，并作为完整知识点制作回听、讲解卡、配音及总卡内容；字幕高亮颜色统一。原片和用户给的音频只作输入，生成中间文件与成片保存在本集工作目录。

建立一份本集 manifest（Markdown、CSV 或 JSON 均可）记录：期数、输入文件及来源、源视频版本、选段时间码、知识点与确认状态、字幕/讲解文稿版本、各知识点对应的 Fish Audio 文件、兔子动画/升级音效来源、输出文件名与版本、质检结果、用户成片确认状态、总卡版本。每次替换素材或修改文稿，更新对应记录，避免混用旧音频和旧视频。只记录文件路径/文件名与版本，不复制不必要的个人信息或密钥。

本公开版只提供可复用的制作规范，不包含任何单集脚本、原片、配音或时间码。按本集素材建立视频、句界、配音、期数和输出文件的映射。

## 制作节奏与交付顺序

1. **输入门**：确认原片可读、期数明确、本集目标清楚。缺期数先问期数；缺原片或关键参考素材，请用户上传。素材不完整时可先做不依赖该素材的工作，并列明阻塞项。
2. **选材确认门**：先给候选片段、原片时间码、准确英文、自然中文、每个知识点的学习价值。请用户确认片段和知识点；若用户要求讨论，继续讨论并更新方案，确认前不做最终剪辑。
3. **文稿与配音交接门**：知识点确定后，在同一次交付中逐点展示 `怎么用` 全文、新英文例句、自然中文，以及每点独立、可直接复制的 Fish Audio 配音稿；全部知识点必须齐全。配音稿只含 `怎么用` 全文和新英文例句，文字与卡片逐字一致。请用户确认文稿；锁定版本后，请用户在 Fish Audio 网页端手动生成、上传对应音频。当前使用免费版流程，不能假设可由 API 自动生成或克隆。每个音频单独标明对应知识点；可按“一点一个音频”交付，也可让用户给出合并音频及准确分段对应关系。仅当听感或内容有歧义时询问是否重录；不得凭文件名猜台词、顺序或对应点。稿件更改后必须重新取得与新稿匹配的音频。尚缺音频时继续字幕、原片剪辑、知识卡版式等独立工作，但不得把不完整音轨交付为完整成片；向用户明确列出待提供的音频。
4. **合成与验收门**：音频和映射齐全后合成，按下文逐项验收并整理预览/截图、时间轴和素材版本清单。发现硬伤先修复并复查受影响项目。手机播放安全区如无法凭现有截图确定，询问目标平台或手机预览素材；不把安全区数值当通用平台规范。
5. **成片确认门**：交付最终候选视频及时间轴，明确请用户确认成片。记录确认的具体文件名/版本。没有确认前，总卡只能按用户要求提供并标记为预览。
6. **总卡与归档门**：确认后制作单张竖向 9:16 总卡；成片任何改动若影响内容、帧图或期数，则同步更新总卡和时间轴。归档最终 MP4、抖音时间轴、确认版总卡、字幕文件、逐点文稿/配音、素材来源与版本 manifest。核对文件存在、名称含正确期数、时间轴对应最终 MP4，且没有把旧版标为最终。

只在缺少必要决策或素材时提问，问题应具体并附上已知选项。例如：期数未给就问“这集是第几期？”；选段/知识点有多种合理方案时给候选供选择；例句语气或中文含义无法从上下文判断时标出歧义；Fish Audio 音频未提供时，发送定稿逐点文稿并请用户按文稿生成后上传；某条录音与卡片无法匹配时请用户指出对应点或重传并命名。不要重复询问已明确的信息，不把可由原片验证的内容转嫁给用户。

## 选段和音频边界

1. 听完整上下文，再选可独立观看的 20–30 秒连续片段。必要时宁可略长，也要让开头与最后一句说完。
2. 为每个讲解点单独定位“含知识点的那一句”，不是整段原视频，也不是只截知识短语。
3. 用转录时间戳找近似位置；逐句听完整原音，并以波形或频谱辅助定位。裁切点必须在最后可听音素（包括词尾辅音、气音、拖尾）完全结束之后；自然余量按配置 `cutting.preferredNaturalTailSeconds`，若下一句或原作者画面切换使余量不可用，则延长或重选片段。ASR 字词结束时间不能单独作为裁切依据。
4. 对配置 `cutting.checkScopes` 中的每一种片段，分别复听最后 `cutting.reviewFinalSeconds`；确认尾词完整并有自然收尾。记录最后可听音素结束点、实际裁切点与两者间隔；若不足配置的最小余量，必须复听并说明原因，必要时延长或重选。慢速版也要保留完整拖尾，重新裁切后字幕须匹配。
5. 复听应使用实际导出的文件，尤其是最后一个词；不能只检查源片或 ASR 文字。若用户听出尾音截断，即使自动参数质检通过，也将尾音项恢复为待复核。静音和人物末帧延续只用于已完整发音之后的视觉与节奏收尾；在 manifest 分开记录源音频裁切点和 `tailHoldSeconds`。靠近下一句时，检查没有带入下一句的起音。用户确认可作为听感验收，但不要编造精确的音素结束时间；没有人工定位数值时，自动余量检查仍保持 `REVIEW_REQUIRED`。

## 字幕与卡片检查

- **字幕框透明度标准：**颜色、不透明度及验收区间取配置 `subtitle.background`。字幕底框由独立的 ASS 矢量矩形事件绘制，每条字幕恰好一块；文字事件不绘制盒式背景，避免行内颜色标签造成底框分片或叠加。从最终成片抽取配置 `subtitle.qaSamples` 列出的句型各至少一帧，避开文字采样框内背景，与同帧未加框画面对比；背景细节必须可见，不允许实心黑块。

- 先从目标发布页截图标出顶部搜索栏、右侧按钮和底部标题/评论/进度条的遮挡，再检查最终视频。对更窄、更高的手机做居中裁切预览；不只检查 1080×1920 原图。当前系列版式：内容卡片约 x=85–920，文字从 x=115 起；顶部人物画面约 x=60–1020、y=230–770；分割线到“怎么用”和“怎么用”到“例句”均留约 45 px。用户指出右侧留白过大后，缩短内容卡右边界，并在不改配音文稿字句的前提下重排换行；仍要逐卡检查长句与右侧按钮是否冲突；实际 UI 改版或手机裁切不同就重新测量。
- 中英文逐句同轴，翻译自然。字幕句末一般无标点；讲解卡上的完整例句正常使用标点。
- 双语框分别依实际文字宽高绘制，文字和框共用同一中心线；测量最终渲染出的字形范围，不能只按估算字符数画框。字幕及讲解顶部回听字幕统一使用配置中的背景颜色和透明度。字号、字体与水平缩放全片固定；长句按语义边界切成不重叠的单行字幕，起止时间匹配原音，原音有自然停顿时可不显示字幕；禁止在字幕内折行、缩小字号或水平压缩。切换字幕时保持固定中心和基线。当前主画面顶边约 y=520、底边约 y=1128；中文框紧靠上方，英文框位于画面底部内侧，二者无交叠。抽查最长句及切换点，检查框的实际像素边界，确认字幕框和画面边缘均留有间距。原速与慢速回听直接衔接；慢速回听尾帧须人工挑选本窗口内人物脸清晰完整、构图得体、表情自然且眼睛睁开的画面，避开闭眼、张嘴变形、脸被切边或主体受遮挡的帧，可在视频尾端短暂停留该帧但不能截断完整音频/字幕。右上回听标签只用于动态回听，并须在慢速视频结束前淡出，停留尾帧和静态讲解卡顶部都不得残留。静态卡顶部复用慢速回听最终实际输出的同一无标签末帧；记录尾帧时间、标签淡出和停留时长及人工审查状态，并作像素一致性检查；停留与淡出时长必须读取配置 `cardLayout.staticTailFramePolicy`，禁止在脚本中另设固定值。水印统一叠加 `assets/兔莫英语学习笔记_固定水印_v1.png`，分别定位在原片/盲听视频及讲解顶部视频**自身的左上角**；程序核查资产 SHA-256、尺寸、透明度和最终成片像素，位置取配置 `watermark`。
- 检查知识点着色范围是否准确，所有入选表达统一暖黄色。没有把非知识词误染色。
- 检查知识卡上“期数 → 英文知识点 → 中文释义”的两段**可见文字边缘间距**相等；不同字形高度通过实际字体边界计算 y 坐标。自动程序从导出卡片的黄色、白色、次级灰色文字像素测间距，容差见 `cardLayout.typography`，不得只比较文本锚点。
- 核对每个回听的源时间：`sourceStartSeconds + replayRelativeStart/EndSeconds`；回听声画必须来自本集已选片段，不得来自整条原片的同名相对秒数。检查知识卡期数均为 `全英VLOG·第XX期`，顶部视频无白色外框。
- 运行 `scripts/qa_replay_source_match.py`，用源片绝对时间抽帧并和每个原速/慢速回听的顶部视频区域作像素对比；最大平均误差读取 `qa.replaySourceMatchMaxPixelMae`。只检查 manifest 中相对窗口范围仍不足以证明渲染程序真的加了选段起点。
- 对照上一期确认成品核查讲解结构：原速回听、0.7× 回听和配音讲解期间，下方同一知识卡内容始终可见；只有顶部视频由动态原片切为人物静帧，回听标签位于顶部视频右上角。卡片底色与两个内容区颜色读取 `cardLayout.palette`，不得以原片模糊色替代系列底色。
- 卡片照片来自当前讲解句附近，脸完整清楚，字幕可见，水印在该照片左上角；集数按 `episodeLabel.format` 写为 `全英VLOG·第XX期`，不得残留旧期数。卡上仅有“怎么用”“例句”两个内容区；两区保留舒适的内部留白，并让分割线到首卡、两卡之间的距离相等。对较长正文按语义断行，不能拆开词语或将标点挤到行首；左右避开互动按钮。新例句确实不同于原句，且用法地道。
- 配音文稿与卡片“怎么用”的全部文字及新例句逐字对应。录音尾字读完；不要以文件名截断文字推断真实音频内容。
- Fish Audio 音频逐条听检：核对说话内容与定稿文稿、知识点映射、开头/结尾完整、音量和杂音。用户手动生成的素材缺失、无法解码或内容不匹配时，列出具体知识点和文件并请用户补交；不要静默跳过该卡或输出缺音的完整版。
- 用户确认成片后制作独立竖向 9:16 知识点总卡；从原片取 2–3 帧拼背景，逐条核对全部知识点的英文、中文和浓缩用法。检查人物面部没有被标题压住，背景仍看得出源画面，且所有文字在缩略预览下可读。

## 转场和合成

- 两处系列转场各约 2 秒，采用 C 款“画面延续”：把前段实际末帧模糊、压暗为转场背景；兔子约占画面宽度 32%，标题、短横线和小字分层淡入、轻微上移，清晰停留约 0.9 秒；元素先淡出，背景再转为下一段实际首帧。片头用做笔记兔 GIF（`assets/兔莫_做笔记动画.gif`），盲听前用听力兔 GIF（`assets/兔莫_认真听听力动画.gif`）。动画必须使用确实不同的写字或点头姿势帧，不能只平移、旋转静态贴图；两帧之间避免眼睛、笔尖重影。各在进入时播放一次《我的世界》升级音效（素材见 `assets/minecraft-levelup.ogg`），及时开始并保留原音完整尾音，不播放旁白或原片音频。第一个转场结束立即进入第一个知识点回听，不加等待卡；其余回听按既有节奏。转场视频播放完整才切换；以本版前后成片的实际端帧生成转场，不要带入旧版底部水印或旧卡片。原速回听结束后直接切入慢速回听，不插间隔或静帧。
- 转场 MP4 导出时按整段时长限制输出，不只用视频帧数限制；历史故障是 `-frames:v` 让音轨在约 1.1 秒处提前结束，尽管原音效和中间 WAV 都完整。分别解码两处**最终成片**的转场音频，确认音效原有的渐弱尾音仍存在，不添加人为回声代替原音。
- 生成透明叠合转场时，用**前段视频实际最后解码帧**作首帧、后段视频实际第一解码帧作末帧，不用近似时间截图。叠合提前数帧到位并保持目标画面，抵消拼接时容器时长取整造成的边界帧丢失。检查的是**最终合成视频**的接缝两帧，而不只是转场素材；两帧不应出现位置跳跃或旧片头闪现。
- 合成前将所有视频片段统一为 1080×1920、30 fps、方形像素、H.264；音频统一为 44.1 kHz、**双声道** AAC。历史故障：单声道知识卡配音与双声道视频直接用 concat 拼接，造成第二个知识点以后丢音。单声道录音应先转为双声道，再合成。
- 静态卡开头给画面约 0.35 秒安定时间，配音全长结束后再留约 0.5 秒。不要按估算字数截断音频。转场和静音段也生成同规格双声道音轨，避免时间戳或布局突变。
- 不直接信任“导出成功”。用媒体信息读取成片时长、画幅、帧率、声道；在字幕段、每个回听、每段讲解配音及无字幕段抽取音频窗口，确认该有声音的地方有非零有效音量。转场仅保留升级音效，其余时段安静。
- 抽帧检查开头、各段交界、至少一张知识卡与无字幕段。确认无黑帧、无旧版本例句、无字幕残留、无遮挡人脸或水印。核对时间轴是根据最终成片时长写的。

## 交付前闭环清单

- [ ] 期数由用户明确提供，素材与版本 manifest 已更新。
- [ ] 选段、逐句字幕及全部知识点已给用户确认；每个知识点都有完整讲解，变更已经同步到文稿。
- [ ] `怎么用`、新例句及中文已定稿；需要的 Fish Audio 录音齐全，且逐点核对无误。
- [ ] 字幕与水印底框在最终成片中符合配置 `subtitle.background` 的颜色和透明度区间；按 `subtitle.qaSamples` 抽帧比对，背景细节可见，无实心黑框。
- [ ] 知识卡与时间轴使用 `episodeLabel.format`；回听与讲解共用完整知识卡，顶部视频无白框，内容卡右边界、底色和三行标题可见间距通过 `qa_series_assets.py --knowledge-card` 抽像素检查。
- [ ] 每个原速与慢速回听来自本集已选片段；manifest 记录相对时间及渲染文件，`qa_replay_source_match.py` 的源画面像素对比通过，并人工核对对应句子的声音。
- [ ] 配置 `cutting.checkScopes` 的各片段最后可听音素均已完整结束；按 `cutting.preferredNaturalTailSeconds` 留自然余量，复听最后 `cutting.reviewFinalSeconds` 并记录时间点；不足最小余量时有复听结论及处理记录。
